**Тип:** `Refactor / Feature`

## 1. Обзор и цели трека (Overview)
Текущая реализация ZIAForge пытается восстанавливать структурированную историю чата (сообщения, рассуждения, вызовы инструментов, запросы разрешений) путем периодического скрейпинга и парсинга цветного текста ANSI-экрана xterm.js (`parseScreenToStructuredFeed` и `mergeFeeds` в `Workspace.tsx`). Это приводит к критическим сбоям: затиранию текста ответов ассистента, схлопыванию повторных вызовов инструментов, зависанию UI и отправке повторных сообщений в неверные сессии PTY.

**Цели трека:**
1. **Переход на событийно-ориентированную модель (Event-Driven Stream JSON):** Перенести управление сессиями и процессами агентов в Electron backend (`RunService`). Запустить адаптеры агентов с нативными потоковыми протоколами (Codex app-server по JSON-RPC, Antigravity CLI и Claude Code через `--input-format stream-json --output-format stream-json`).
2. **Разделение вывода (Terminal vs Chat Feed):** `TerminalPane` отображает сырой поток консоли xterm.js; `ConversationFeed` рендерится строго из типизированного append-only журнала событий `EventJournal` (`message.delta`, `tool.started`, `tool.completed`, `permission.requested`).
3. **Декомпозиция монолита `Workspace.tsx`:** Разделение 4130 строк на независимые изолированные модули (`ConversationFeed`, `TerminalPane`, `Composer`, `ApprovalCard`, `PlanPanel`, `WorkspaceShell`) размером до 300-400 строк с оптимизированным Zustand store.
4. **Устранение коренных дефектов маршрутизации:** Жесткая привязка сессий, логов и каналов ввода к `taskId`/`runId`, устранение глобального поиска процессов по строке и фолбэка PTY в `$HOME`.
5. **Подключение тестовой среды и честного TDD-автомата:** Инсталляция Vitest, покрытие критических путей тестами (>80% coverage) и реализация механизма верификации задач (Red -> Green -> Commit) в изолированном Worktree.

## 2. Функциональные требования (Functional Requirements)

### 2.1 Backend Execution Layer (Electron)
- **`RunService` & `SessionRegistry`:**
  - Централизованное управление жизненным циклом запусков задач (`runId`, `taskId`, `sessionId`).
  - Гарантированный запуск в целевом каталоге задачи (`cwd = task.worktreePath`). Запрет запуска в домашней директории при ошибке пути.
  - Идемпотентный запуск задач: повторный вызов `start-task` возвращает существующую сессию без разрушения данных.
  - Привязка PID к сессии задачи и завершение только дочерних процессов текущего запуска.
- **`EventJournal` (Потоковый журнал событий):**
  - Запись событий в формате append-only NDJSON в `artifacts/worktrees/<taskId>/runs/<runId>/events.ndjson`.
  - Типизированные события `AgentEvent`:
    - `message.started`, `message.delta` (потоковый текст/thinking), `message.completed`.
    - `tool.started`, `tool.output.delta`, `tool.completed`.
    - `permission.requested`, `permission.state.changed` (`submitting`, `resolved`, `expired`).
    - `verification.completed`, `workflow.step.changed`.
  - Поддержка Replay и восстановления истории чата без обращения к терминалу.
- **`ApprovalRegistry`:**
  - Учет активных запросов разрешений с уникальными `approvalId`.
  - Прямая доставка ответа пользователя (разрешить/отклонить) в ожидающий RPC-запрос без эмуляции нажатий клавиш в активной вкладке.

### 2.2 Адаптеры агентов (Agent Adapters)
- **Codex Adapter (Эталонная реализация):**
  - Подключение `codex app-server --listen stdio://` с двусторонним JSON-RPC протоколом.
  - Поддержка `item/agentMessage/delta`, `item/started`, `item/completed`, серверных запросов `item/commandExecution/requestApproval`.
- **Antigravity CLI Adapter:**
  - Запуск `agy --input-format stream-json --output-format stream-json`.
  - Декодирование NDJSON потока событий `init`, `step_update`, `result`.
- **Claude Code Adapter:**
  - Запуск `claude -p --input-format stream-json --output-format stream-json --include-partial-messages --verbose`.
  - Обработка `stream_event` дельт без дублирования с финальным `result`.

### 2.3 Декомпозиция UI (Frontend React)
- **`WorkspaceShell.tsx`:** Каркас рабочей области, управление панелями и вкладками.
- **`ConversationFeed.tsx`:** Чистый рендеринг истории чата из `EventJournal` с поддержкой markdown, блоков размышлений и инструментов.
- **`TerminalPane.tsx`:** Автономный терминал xterm.js для просмотра реальных логов и запуска shell-команд без влияния на состояние чата.
- **`Composer.tsx`:** Поле ввода, выбор модели, переключение режимов, прикрепление файлов.
- **`ApprovalCard.tsx`:** Интерактивные карточки запроса разрешений с явным статусом (Pending, Submitting, Allowed, Denied, Expired).
- **`PlanPanel.tsx`:** Отображение чек-листа задач трека и статуса шагов.

### 2.4 Автономный TDD-цикл (Workflow Engine)
- Реальный запуск команд тестирования через `VerificationRunner` в каталоге Worktree.
- Фиксация статусов Red (тесты упали с ожидаемой ошибкой) и Green (тесты успешно прошли).
- Лимит повторных попыток исправления (до 3 раз) с остановкой при повторяющихся сбоях (Circuit Breaker).
- Автоматическое создание Git-коммита только после успешного прохождения проверок.

## 3. Нефункциональные требования (Non-Functional Requirements)
- **Стабильность и производительность UI:** Время реакции ввода в Composer < 50 мс; отсутствие каскадных ререндеров ленты при потоковом выводе логов; отсутствие фризов при потоке данных до 10 МБ.
- **Целостность данных:** Нулевая потеря текстовых дельт и сообщений при переключении между вкладками задач.
- **Качество кода и тестирование:** Покрытие нового ядра тестами Vitest > 80%; ноль ошибок `tsc --noEmit` и ESLint.
- **Безопасность:** Запрет глобальных `pkill` по строкам команд; строгая изоляция действий внутри worktree.

## 4. Критерии приемки (Acceptance Criteria)
1. **Тесты ядра:** В проекте настроен Vitest (`npm run test`), юнит-тесты `RunService`, `EventJournal` и адаптеров проходят со 100% успехом.
2. **Сквозной стриминг чата:** При отправке сообщения в задачу текст ответа агента появляется плавно в `ConversationFeed` в режиме реального времени без потери фрагментов и без артефактов ANSI.
3. **Раздельные каналы:** `TerminalPane` отображает сырые логи процесса, а `ConversationFeed` отображает форматированный чат. Очистка терминала не влияет на историю чата.
4. **Надежные разрешения:** Карточки `ApprovalCard` четко принимают клик "Разрешить"/"Отклонить", агент немедленно продолжает работу, статус разрешения корректно фиксируется в истории.
5. **Изоляция вкладок:** При одновременной работе задачи A и переключении пользователя на задачу B логи задачи A не попадают в ленту задачи B; повторная отправка промпта в задачу A отправляется строго в сессию задачи A.
6. **Декомпозиция файла Workspace:** Размер каждого из выделенных компонентов не превышает 400-500 строк.
7. **Автономный TDD:** Запуск контрольной тестовой задачи фиксирует реальный Red (падение теста) -> Green (прохождение теста) -> коммит в ветку worktree.
