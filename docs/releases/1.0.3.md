# ZIAForge 1.0.3

This stable patch addresses settings saves on Windows, including a reported interface-language change that did not persist. It also makes failed saves visible in Settings.

## Changes

- Windows storage updates no longer attempt the unsupported directory flush that could reject a settings save. Regular files are still flushed before atomic publication; file-write errors remain errors. Supported directory flushes on macOS and Linux are preserved.
- Settings waits for a save to finish, prevents duplicate submissions while it is pending, and displays a caught save error so the user can correct the cause and retry.
- An acknowledged settings save applies the new language immediately. A later project-list refresh failure retains the existing projects without reporting the completed save as failed.
- Generated HTML guide headers follow the package version automatically. The canonical help content and translation status are unchanged.

## Verification

Focused storage/editor regressions (21 tests), Settings save/retry regressions (4 tests), TypeScript and lint of the changed TypeScript files passed. Related preference/capability checks also passed. These are local source/component checks.

The [native Windows storage regression](https://github.com/ZIAForge/ZIAForge/actions/runs/37646880744) passed on Windows Server 2025 x64 and Windows 11 ARM64 with Node 24.21.0. The 1.0.2 baseline reproduced `EPERM` from directory `fsync` without changing the original settings. Patched code passed repeated saves, recreated-store reads, a cold-process read/save, dead-owner recovery, bounded backups and asynchronous metadata replacement. Regular-file flushes remain enforced. The exercised source hashes are retained in each workflow receipt; a filesystem probe does not establish an installed application's GUI behavior.

Fresh six-target compilation/package checks retain the frozen source identity, architecture checks and checksums in the release manifest. Those build receipts are separate from the targeted regressions above.

No application launch, GUI/installer/upgrade check, live provider request or complete regression-suite run is planned for this patch. Those checks must not be inferred from successful compilation or packaging.

## Downloads and installation

Packages use one frozen source commit for macOS Intel x64 and Apple Silicon ARM64, Windows x64 and ARM64, and Linux x64 and ARM64. macOS receives DMG and ZIP; Windows receives installer EXE and ZIP; Linux receives DEB, RPM, AppImage, tar.gz and ZIP. Source archives, notices and `SHA256SUMS` accompany the release.

Packages remain **unsigned**: macOS is not notarized and Windows has no Authenticode signature. Fully quit the application before manually replacing an installation, keep the existing user profile, and verify the downloaded checksum. See the [platform installation instructions](../PLATFORM_BUILDS.md).
