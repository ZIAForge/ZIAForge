# ZIAForge 1.0.11

This patch fixes premature interruption of long Claude Connector requests. An active response could previously be cancelled by the application's fixed ten-minute timer, even while the connector was still streaming.

## Changes

- Claude caller and native sessions read the connector's advertised turn deadline. Each Messages request receives that budget plus five seconds of transport grace. Older connectors without this field keep the existing fallback; server, tool and interaction limits still apply.
- Output-budget exhaustion (`max_output_tokens`), server timeout, client deadline, expired questions and owner Stop retain distinct failure information. A matching failed-response receipt confirms that remote work has ended without converting partial output into success.
- New Claude connections default to 128,000 output tokens. Thinking shares that budget with the answer; the earlier 4,096 default could be exhausted before an answer or complete tool call. Saved explicit budgets and chat settings are preserved.

Update the connector server as well to advertise its longer deadline. For an existing connection, review its output limit in **Connections**, save it, and explicitly apply it in the chat. Saving settings alone does not change an active run. A task interrupted by an earlier release is not automatically resumed or resent: inspect its history and any recorded effects before creating a new context.

## Verification and distribution

Focused checks cover active streams beyond ten minutes, caller continuations, advertised and explicit deadlines, question expiry, confirmed Stop, terminal error classification, saved budgets and the no-replay boundary. Package jobs compile and verify the six OS/architecture targets; they do not repeat native installer, GUI or provider checks on every system. No original user task is replayed for validation.

Packages cover macOS Intel/Apple Silicon, Windows x64/ARM64 and Linux x64/ARM64, with source archives, notices, manifest and SHA-256 checksums. Packages remain unsigned and macOS is not notarized. Keep normal OS trust prompts enabled. From version 1.0.9 or newer, use **Settings → Updates**.
